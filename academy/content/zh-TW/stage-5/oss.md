# 開源與影響

> 對應 Goal：`G5.15`, `G5.16` ｜ 練習預估 8 小時（包含專案與反覆練習，不是閱讀時長）
> 前置：G5.14

## 為什麼學這個

把作品交給另一個人實際使用，讓協作留下可查核的紀錄。

## 概念

公開成果要有問題、安裝、最小範例、限制、授權與維護入口。對上游貢獻先讀 CONTRIBUTING，選可重現的小問題，避免把多個無關更動塞進 PR。回饋必須来自真實使用者，不能把自己的演練說成外部驗證。

## 動手

從倉庫根目錄執行；獨立 Python 片段先存成練習檔再執行。帶有「你要交付」的命令是作業介面，需要先自己完成程式。

```bash
git status
git diff --check
python3 -m pytest -q
# 本機確認後，在自己的公開 repo 準備版本化 release
# 對外提交與訊息由作者依專案規則執行
```

### 預期結果

測試通過是交付的一部分；它不會自動產生被合併的 PR、讀者或真實回饋。

## 練習與驗收

選「自己的開源發布」或「上游合併 PR」完成 G5.15，保存 URL、commit、checksums、安裝與回退步驟。以一篇文章或短講完成 G5.16，請讀者試一個明確任務並記錄原話、障礙與修改。未獲回覆時在進度保持待回饋。

## 常見坑

不要替 reviewer 虛構意見，不要以下載數代替成功使用案例。引入第三方圖片與程式要保留授權與來源。

## 自測清單

- [ ] `G5.15` 向開源專案提交一個被合併的 PR，或發布自己的開源專案。證據方式：`portfolio`。
- [ ] `G5.16` 發布一篇技術博客或一次演講並收集真實回饋。證據方式：`portfolio`。

`ready` 表示教材可閱讀，並非你已完成目標。自動檢查只驗其明列契約，專案、外部回饋與人工解釋需留下真實證據。
