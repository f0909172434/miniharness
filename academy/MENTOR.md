# 導師手冊

先用 `map` 與 `next` 查看自評進度，再請學習者展示該階段 exit Goals 的實際產物。`done` 是自評，`verify --reference` 是教材自檢；两者都不能替代學習者驗收。

每次階段評審可用 20–30 分鐘：

1. 請學習者用自己的話說明一個 `know` 目標，再改一個條件追問。32 題 quiz 只提供初步自測，猜中選項不算完整理解。
2. 從空目錄重跑一個 `do` 目標，觀察是否依賴未寫進 README 的路徑或套件。
3. 對 `build` 目標檢查 [交付清單](ASSESSMENT.md)，要求說明一個設計決定與一個失敗例。
4. 執行 `verify` 驗學習者作業，記下命令、日期、退出碼與原始輸出。缺作業或 timeout 保持未完成。
5. 指定一個故障修改，確認測試會發現它；再修回。整理仍不清楚的概念與下一次練習。

## 評審記錄

```text
日期／學習者自行選用的識別：
階段、Goal、作品 revision：
執行環境與命令：
觀察到的正確行為：
故障案例與修復：
仍需練習：
下一步：
```

連續七天練習、實際 GPU 操作、公開基準重現、上游 review 與真實讀者回饋，都要有對應時間或外部記錄。沒有記錄時保留待完成。作品展示先取得學習者同意，移除私人資料；維持真實負結果，不用完成率取代學習。
